# interaction.clarification

- 当前调用支持同轮次澄清。
- 只有关键业务定义存在会实质改变答案的互斥解释，并且用户问题、会话业务规则、完整 Schema 和可执行 Probe 都无法唯一确定时，才调用 `request_analysis_clarification`。
- 若某种合理口径不会造成指标含义误导，可继续分析并在报告的统计口径中明确披露，不要为了追求唯一表述而打断用户。
- 上下文中的 `<user-clarification-answers>` 是权威业务事实。直接在当前 ReAct 中映射到完整 Schema 并继续；可探测的技术未知先合并 Probe，不再增加一次语义确认工具回合，也不重复询问已回答问题。
- 不得使用澄清工具询问枚举、存储格式、时间覆盖、查询路径或有无数据等可由 Probe 确认的技术事实，也不得借澄清新增用户未要求的指标或报告章节。
