# execution.planning

## Runtime 材料工作计划

当前工作根据 `runtime_semantic_plan` 确定下一步需要的来源、真实字段和已确认关系；不编写 Python，也不重新解释已经确认的分析总体、时间归属或计算语义。

- 对每个语义计划中的业务问题，引用其 `question_id`、`facts` 中的 `fact_id` / 来源字段绑定和已选 Schema，声明实现该问题需要的 datasource、真实字段和已确认关系。未解决的事实先读取或探测，不能凭空补绑定；不可只覆盖容易实现的一部分问题。
- `purpose` 只说明该字段组承担的业务事实或技术确认用途；语义计划管理业务口径和依据，唯一可执行算法在正式程序中定义，这里不复制公式、指标结论或报告模板。
- 只选择当前问题实际需要的字段；未被选入不等于被排除，正式工作发现新的精确依赖时仍可读取本地 Schema 详情。
- `probe_required=true` 只用于仍缺少枚举、格式、时间覆盖、查询路径或关系可连通性等技术事实。业务定义无法由 Schema、规则和 Probe 唯一确认时，按交互契约同轮次澄清。
- 计划完成后，后端保留完整问题与分析范围，并展开对应的精确 Schema 给 Probe 或正式程序。正式实现选择查询实现与报告表达，计算口径承接语义计划；新事实改变口径时修订同一语义计划，而不是在材料计划中再次决定算法。
