# execution.planning

## Runtime 材料工作计划

当前工作只把完整洞察语义组织成一份可执行前的数据模型，不编写 Python，不定义指标公式、图表、表格、报告章节或结论。

- 对每个用户业务问题，引用 Preparation 已有的 `question_id` / `fact_id`，声明实现该事实需要的 datasource、真实字段和已确认关系。
- `purpose` 只说明该字段组承担的业务事实或技术确认用途，不能提前写计算公式、排名权重、指标结论或报告模板。
- 只选择当前问题实际需要的字段；未被选入不等于被排除，正式工作发现新的精确依赖时仍可读取本地 Schema 详情。
- `probe_required=true` 只用于仍缺少枚举、格式、时间覆盖、查询路径或关系可连通性等技术事实。业务定义无法由 Schema、规则和 Probe 唯一确认时，按交互契约同轮次澄清。
- 计划完成后，后端把它转换为 Runtime 数据模型：保留完整问题与分析范围，并只展开对应的精确 Schema 给 Probe 或正式程序。最终 Runtime 仍独立决定查询、算法和报告表达。
