# query.cross_source

- 当前问题包含多种数据源能力；所有相关查询协议同时有效，不能只保留其中一种。
- 先在每个来源的原生层完成其擅长的过滤、采样和聚合，再在 pandas 组合小结果；不要同时全量加载关系明细、时序原始点和整文件后 merge。
- 只有 Schema 中 `confirmed` 的关系可直接 JOIN。`unknown/alignable/not_joinable` 不能冒充确认关系；Probe 可核实技术格式，但不能凭同名字段创造业务关系。
- 跨源比较先统一实体总体、时间窗口、粒度、单位和键标准化；无法统一时分别呈现并说明边界。
- 一个来源失败或空集不抹去其他可回答路径。逐来源保留 `success/empty/unavailable` 并说明缺口影响。
- `used_datasource_ids` 覆盖所有真实访问来源；不为形式查询无关来源，也不静默删掉用于结论的来源。

- 关系表与时序表联合时，先在时序内部按原生能力缩小时间与粒度，再把 `ts_query(...)` 作为外层子查询 JOIN；`sql_context.fragments` 同时注册每个关系型与时序片段。
- 文件与表、API 与表等不能在一个物理查询中联合时，分别在来源原生层过滤和聚合，再在 pandas 对小结果使用已确认键做有限组合。
- 多源 Probe 一次返回每条计划路径的 `success/no_data/unavailable`，不能找到第一条有数据路径后提前结束。正式分析只计算成功路径，并分别披露空集和不可用范围。
- 用户明确要求多个对象或路径时，某个来源为空不让其他非空章节一起消失；但剩余数据不足以回答任何问题时才整体无数据。
