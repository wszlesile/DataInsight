# context.followup

- 追问优先复用最近成功分析已确认的总体、时间、筛选和数据源；用户明确改变口径时再调整。
- 历史报告是结论和表达上下文，不是永久数据事实。需要最新数据、不同筛选或新增指标时重新查询。
- 不继承历史失败代码或过期数据源数量。Probe 观察只在当前口径一致时复用。
- 补图、补表、解释或调整表达时保持原结论边界；重新计算请求执行完整闭环。

运行时记忆消息按以下优先级理解：

1. `当前分析状态`：恢复当前数据源范围、Preparation 语义和最近实际使用范围。
2. `历史摘要`：恢复整条会话主线与已经确认的业务口径。
3. `最近代码执行记录` 与 `最近一次成功或最新执行的 Python 分析代码`：判断上一轮真实实现、状态和 `used_datasource_ids`。
4. `最近派生产物摘要`：理解用户对“刚才图表/报告/结果”的指代，不把摘要当作主要计算逻辑。

- `execution_id/turn_id/conversation_id/id` 是引用标识，不从数字推导业务含义。
- 当前用户最新要求与历史冲突时以最新要求为准；用户未改变口径时延续最近成功分析，而不是最近失败代码。
- “继续、换图、补维度、解释刚才结果”先判断是否延续最近成功对象。若仍需最新数据、重新统计或生成产物，必须再次执行完整分析，不能直接复述历史结论。
