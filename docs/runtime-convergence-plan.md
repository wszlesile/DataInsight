# Runtime 收敛设计与实施计划

## 目标和范围

基线 be9d3fd7。保留统一 ReAct 下生成完整 Python 洞察程序的语义所有权，
以状态、有效记忆和按工作组装的上下文降低同时认知负担。不是退回静态大
Prompt，也不是新增线性业务 Stage。保留澄清、外部分析、Probe/no-data、
多类数据源、Evidence、本地执行及任务功能。

本文归纳当前已发现问题，并非宣称未知问题已全部排除。证据路径见
[联合行为核验](runtime-focus-memory-joint-audit.md)。

## 实施顺序

### A. 工作与材料一致性

复用消息作为完整审计源，单一 reducer 产出当前工作、焦点、字段材料范围。
Probe 子工作保留父工作及材料；新显式材料请求替换当前局部视图，不缩减
全局选源。成功观察恢复父材料；Probe 自身失败保持子材料以便修复。
无显式材料请求沿用当前视图。计划是可修订工作成果，不是永远不可变范围。

验收：实现 -> 新字段 Probe -> Probe 修复 -> 恢复实现；修复同理；新计划
明确替代旧计划；序列化事件恢复等价；原消息不变；协议/工具与工作一致。

### B. 全局语义与精确资料

全局问题、覆盖和未知索引不能随焦点被过滤。局部详细 Schema 继续投影。
扩展既有读取能力以获取 Preparation 的原始业务血缘依据，而非让模型
只能看到裁剪后的版本。用确切 ID 和来源定位，不增加新的业务规划 Agent。
每份正文只在一个载体上交付，不能把完整快照重新塞回每次 system prompt。

验收：材料计划漏选某事实时仍可发现并补载；关系安全条件/推导依据不丢；
混合数据源协议并集完整；补读不改变全局覆盖、不重启工作。

### C. 有效记忆与修复承接

逐项复核 program/patch/diagnostic/query/probe/reference/analytical-note 的
身份和替代规则。确定性替代使用类型化来源，不能解析叙述后武断删业务判断。
当前完整代码与当前诊断必须保留；旧失败不代表新版本仍失败，也不代表已
解决。重复事实按查询和范围去重；新范围不能覆盖旧范围的观察。

验收：完整替换/patch、Probe 后续正式修复、多次查询不同口径、外层续跑、
澄清恢复；消息协议完整配对；资料不会每次重投成倍累加。

### D. 控制调用与能力完整性

完成 A-C 后再判断无增量控制调用是否合并。以实际信息成果衡量，不为了
省一轮调用放弃必要 Schema，不为了限制循环封锁合法工具。对照基线契约
逐项检查代码规范、文件/时序/关系/混合查询、输出模式、取消和澄清。

### E. 验收

先无网络测试，包括实际 create_agent 循环、消息序列化恢复和能力保持。
然后本地连接 226，空间 15，串行：44/64 文件简单分析、45/65、43/63、
46/67，再按空间实际轮次核对 47/48。关联数据源/Provider 遵循当前业务逻辑，
不在生产代码硬编码回归路由。权限、网关与 FedQuery 先检查，不把环境故障
当成设计失败。不默认改写历史 Evidence。

每次记录 Preparation、模型逐次输入/输出与时延、控制/Probe/正式提交/修复
数量、执行、Evidence、端到端；不能只记总 token。逐项核算核心指标、口径、
空数据/部分数据说明、报告业务价值、图表表格可用性和 Evidence 完整性。
与相同环境的历史轨迹仅作参考；宣称优于基线需可比运行，不以一次成功证明。

## 推进纪律

每批先说明缺口、改动边界和联合验收，再改代码。失败若属设计，应补齐联合
行为；若属实现，修契约错位；若属环境，记录阻塞，不加业务兜底。未通过的
事项留在矩阵，不转头修别处后遗忘。未完成 A-D 不启动批量真实复跑。
真实 token 失效时明确需要更新，不在报告中泄露认证信息。无擅自提交、部署、
删除用户修改或服务资源。
