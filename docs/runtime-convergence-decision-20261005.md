# Runtime 收敛决定与交付门槛

日期：2026-10-05。基线：`release/V1.08.02.00-C@e85adcb` 加现有未提交改动。
本决定回答“为何多轮推进仍未收敛”。详细过程见 `current-architecture-and-next-steps-20261005.md` 第 8–11 节；本文件是当前推进决定，不以历史试验的阶段完成替代交付。

## 当前结论

最新推进边界：先按 [语义到执行闭环设计](runtime-semantic-execution-contract-design.md) 完成职责、接口和证明边界；停止从单个报告错误挑选局部候选。该设计仍有明确未解决项，不能作为已验收或已上线方案。

有定位与来源承接边界的进展，**没有新增已验收的完整业务结果，也没有已验证的全链路性能提升**。当前不可据此交付或宣称接近达标。

| 工作 | 可确认的结果 | 不能据此确认 | 决定 |
| --- | --- | --- | --- |
| Preparation 来源区分 | 原始定义保留，模型解释独立记录，自评 confirmed 不再升格 | 三次真实补全仍把安装日期解释为投用日期 | 保留来源修正，语义准确性仍阻塞 |
| 长表达示例 | 冻结请求可比较 | 完整报告正确或性能改善 | 候选已撤回，停止同类扩大 |

| 默认暴露结构化比较 | after 3/3 首次执行成功；确实调用比较函数 | 完整报告仍 0/3；生成中位数 42.562 秒，没有全链路对照 | 候选已撤回，停止同类扩大 |

不同试验的 baseline 有复用，边界也不同，不将样本、测试和数据变体合并成一个通过率。0/3 是该组交付失败记录，不是总体概率估计。

## 为什么没有收敛

1. **设计边界未闭合。** 计划中的计算定义和判断依据主要是模型声明；实现引用正确不证明公式、总体、粒度正确。正确的比较事实旁边仍可存在独立自由字符串，例如“存在差异：所有类型数量相同”。
2. **来源修复与业务语义修复不同。** 记录解释来自模型，能避免把解释误当权威定义；不能使解释本身变正确。
3. **验证边界有局限。** 正式提交包含完整查询、计算、报告和保存。worker 执行成功后主线进入 COMPLETED；源码合法、表格正确、Evidence complete 各自不能认证整段解释。保留的 Review 接口不代表主线经过业务复核，也不把恢复事后 Review 作为此处修正。
4. **推进方式需要纠正。** 连续补充示例、函数暴露和构建方式改善了局部边界，却没有改变错误判断的生产路径。应该更早停止这些等价路线。不能把一个试验结束或测试通过包装成产品进展。

相关代码边界：`src/agent/runtime_driver_state.py` 正式成功转 COMPLETED；`src/agent/__init__.py::stop_after_saved_analysis`；`src/agent/tools.py::submit_analysis_program` 与 `_execute_generated_code_worker`。这是链路事实，不证明缺少一次模型观察是所有错误的原因。

性能主要待收敛的是模型回合、全文重写/修复及 Evidence 尾部调用。Python 单次执行耗时不能代表全链路成本。增加模型观察回合也可能增加耗时，目前没有净收益证据。

## 立即固定的边界

- 不再追加等价 Prompt、结果用途属性、相近 helper 或草稿持久化。
- 不将拆分大型模块混入准确性实验；当前跨层未提交改动保留，未因本决定整体撤回。
- 不通过缩减报告、限制分析种类、业务词面门控、加入 Report Agent 或事后模型审核提高表面通过率。
- 不把“让模型先看到实际事实”直接当作解决方案：它尚未验证，也不能证明同一程序在无模型重跑时会正确改变判断。

## 下一项机制的准入条件

下一项候选必须处理**完整判断段落及建议的生产路径**，而非再提供一个可绕过的局部事实句。当前尚没有通过以下条件的候选，不能先宣称已经找到最终架构。

先用手工写出的普通 Python 完整程序证明候选能承载正确行为，再请求模型生成。手工程序只是机制可表达性的检查，不计作模型通过，不借手工程序缩减后续生成范围。

候选必须明确交代：

1. 哪些计算值、完整比较总体、业务规则和未知条件输入实际段落生产者。
2. 段落与建议如何由当前结果求值；为何旁边固定前后缀不会再建立第二套判断。只有函数引用、依赖声明或出处索引不足以回答。
3. 如何保留普通 Python、自由叙事、图表表格、多源查询与无模型本地重跑。
4. 对任意自由业务推断还剩什么未认证边界。结构约束只能证明结构，不声称能够认证任意文字的语义。
5. 新增调用、上下文和执行成本；不把额外生成回合从统计里移除。

候选若无法回答这些问题，就不进入真实三次生成试验。不能用更多生成代替设计。

## 后续机制检查：普通 Python 整段生产者

已完成两份手工参考程序及负对照。设备段落将完整分布、状态分支和后续核查放在同一函数中生成；成本程序先按销售利润表核算金额，再独立连接单位生产成本，区分销售加权情景与实际生产成本。使用现有正式 worker、原查询 helper、真实保存/图表表格校验，以及保存后的结果结构校验。只替换文件传输返回的 fixture，不修改原文件或洞察数据库。

修正后的固定批次共 17 次：设备 8 个输入、成本 7 个输入、2 个负对照。12 份正常非空参考报告完成结构化交付且已实现的独立事实核对均通过；2 个空集保留 no_data_found，1 个重复业务键保留 runtime_error。空集和重复键未完成最终无数据/澄清交付，不能计作整体验收通过。另用 openpyxl、Counter、Decimal、独立日期解析核对设备事实，及此前成本独立核算，共 68 个检查无失败；它们不是 68 个模型样本或报告通过。

**关键反证**：在正确整段生产者外添加“设备类型分布存在差异”，四维等量下仍通过源码、保存、结果结构校验；在成本报告前添加“实际生产成本已确认等于销售结转成本”，缺少生产数量时也通过上述校验。两份分别是事实冲突和无依据确认，业务评审失败。不得为使本试验通过而增加禁止这些词句的门控。

定位到一个直接的关键路径设计问题：`ConversationContextService` 在成功结果提交之后，同步调用可选的 `EvidenceAssemblyService`，再返回分析产物。Evidence 失败不会回滚报告，但它的多个 LLM 规划调用仍阻塞当前任务完成。44/64 的该段约 237 秒，明显主导总延迟；后续改为可恢复、状态可查询的异步 Evidence 生命周期，不能简单丢弃引用、降低覆盖要求或以语义校验重试换取速度。

**当前“候选计算后另起表达模型回合”的机制不准入。** 它增加了表达回合，却没有消除完整报告中的自由语义误判；45/65 的表达结果仍错误，44/64 仍存在数值和口径问题。此结果只能说明阶段边界可以执行，不能宣称准确性提升。暂停该机制的进一步扩展与生产接入；下一架构候选仍须先通过本文件规定的整段生产者反例检查，并同时说明 Evidence 如何退出同步关键路径而保持可恢复性。

## 2026-10-07 Evidence 关键路径改造

已在工作区实现持久化异步生命周期：分析成功后创建 `queued` 状态并返回；独立 Evidence Runner 条件抢占并执行原编译器，完成后写回原有证据包、产物引用和 `complete/partial/failed` 状态。Runner 对 15 分钟无更新的 `running` 记录重新接管；轮次详情提供 `evidence_compilation`，使客户端能够查询状态。部署至少需要一个 `all` 或 `task-runner` 实例运行消费者。

该改动只移除 Evidence 编译对分析请求的同步等待，不改变解析、引用覆盖、语义质量或模型调用数，也不引入语义门控和语义重试。因此它有明确的延迟目标，但尚未通过运行态并发/中断验收，不能声称当前环境已提速或已经投产。准确性目标仍按上节两例及既定完整验收矩阵推进。

## 2026-10-07 Runtime 性能复核

Evidence 移出请求关键路径后，Runtime 仍有独立成本。两条 SSE 时间线显示：45/65 的 Preparation 约 48 秒，Runtime 约 294 秒；44/64 的 Preparation 约 64 秒，Runtime 约 190 秒。Runtime 内仍串行经过语义规划、资料读取计划、程序生成、程序执行与表达；45/65 两次程序修复，44/64 三次正式提交后才成功。它们不是严格同期对照，不能据此声称当前代码造成具体幅度的变慢。

复核详情与执行记录发现一处可确定的无效修复回合：本地文件契约允许用 `年月 == "2026-03"` 表示单月范围，时间范围识别器却只把 `YYYY-MM-DD` 解析为月边界。44/64 第二次生成已用实际执行的精确月份 `file_filters`，仍因未识别 `YYYY-MM` 边界而返回“缺少 end”，触发了第三次生成。`_month_grain_filter_satisfies_time_range` 现同时接受 `YYYY-MM` 与 `YYYY-MM-DD` 月初边界；精确单月过滤可通过，跨两个月的同一过滤仍会失败。该修正只消除契约认可实现的误判，不改变实际筛选，不放宽范围，也不引入新的语义审核或重试。

针对该错误的定向测试为 13 项通过，包括单月精确过滤通过、跨月范围不被单月过滤冒充。尚未通过真实服务复跑验证节省的端到端时间；44/64 第一次提交仍确实缺少过滤实现，应继续反馈修正。45/65 的首次程序把数据源路径写错，下一版修正路径后又遇到 `build_chart_result` 不支持 `include_line` 参数。

为消除这类长路径抄写错误，`query_local_file` 与 `query_local_file_low_memory` 现在可接收当前回合选中的 `datasource_id`，执行 Worker 根据受选范围的数据源快照解析真实文件标识；未选中的 ID 会在加载前被拒绝。旧 `file_path` 调用保持兼容，若同时传入 ID 与不同路径则报错。Preparation 将当前选择的 ID/标识映射随已有 Worker 上下文传递，没有引入新数据库状态。Prompt 契约已改为优先使用 ID。该改动不扩大可访问数据源，不改变过滤或读取粒度，预计可避免路径幻写造成的失败；仍需真实服务复跑确认效果。

继续追查模型可见的函数签名时，还发现 dataclass 工具 `PythonCalculation` 将 `parameters` 的默认工厂渲染为非法 Python 字面量 `<factory>`。`runtime_helper_signature` 现在把这类默认显示成有效的空字典，并保留 keyword-only 参数边界，避免将不能执行的接口说明交给模型。

文件查询、日期范围、Worker ID 路径解析、helper 签名和 Prompt 能力对齐相关测试共 **221 项通过**。没有真实服务复跑、提交或部署。
