# 可执行分析核心隔离原型：版本约束成立，准确性未改善

基线：`release/V1.08.02.00-C@e85adcb` 加当前未提交改动。环境：本地真实文件/合成输入；一次实际 226 模型网关调用。没有生产注册、洞察数据库写入、部署或服务/隧道启动。

## 机制及实际边界

语义所有者发布一份普通 Python 源码，包含查询、参数、计算、判断、整份正文、建议和图表表格含义。装配输入只允许 core_id/revision/digest；宿主验证版本与源码身份后，拼接已有 save_analysis_result 终态。外层没有报告字符串、标题、公式、图表语义或补丁参数。生成出的完整源码仍使用现有查询、worker 和产物校验，可以从头执行。

原型在 `.codex-work/sealed_analysis_core.py`，未接入正式 Runtime。它约束的是**发布之后的装配输入**，不是分析正确性认证，不是 Python 安全沙箱。普通 Python 自由表达仍在核心内部，错误公式、静态前缀、无依据建议也可能在内部出现。模型可以在同一次生成中建立多套不一致判断，不需要经过第二次外层生成。

修订核心必须显式产生新版本，旧版本仍可引用。原型仅实现初始版本快照恢复，不代表完整修订持久化、取消、澄清、修复和 Evidence 集成已经完成。不得将 source hash 对应到业务真值。

## 手工机制检查

7 项单元测试通过，覆盖外层扩展输入拒绝、版本身份、源码不可变、显式修订及旧版本保留、快照恢复、错误核心仍可发布、宿主终态与语法检查。

复用设备/成本参考及原反例集合，共 17 次隔离执行。每个核心分别尝试报告前缀、完整正文、源码、补丁、图表及公式 6 种装配输入变更；102 次尝试全部拒绝。它们重复使用相同严格接口，不是 102 种独立攻击，也不证明恶意 Python 不可能越权。17 次恢复得到相同装配源码。

12 份正常非空参考完成结构化交付且已有独立事实核对通过；2 个空集保留 no_data_found、1 个重复业务键保留 runtime_error。两份额外故意写错的核心仍能保存并通过结果结构校验，业务失败：等量数据中声明设备类型存在差异；缺生产数量时确认实际生产成本等于结转成本。**核心内容错误仍然未受身份约束控制。**

从成本核心快照恢复后，用真实本地 CSV 分别执行三月、二月。两次均重新执行两条物理查询，覆盖参数变化；金额与独立 csv/Decimal 参考一致，结果结构校验通过。零模型调用、没有复用草稿 DataFrame。这是 worker 重放，不是本地重跑服务入口与完整 Evidence 验收。

手工报告只是可表达性证据，成本参考没有完整展开原问题的产品/车间/产线分析，不能作为缩减范围的生产模板或完整验收基线。

## 一次真实核心发布筛查

手工装配身份边界成立后，执行一次独立发布筛查。保持已有人工核对计划、Schema 和冻结历史，仅将提交形式切换到 publish_analysis_core；唯一保存终态由宿主拼接。不增加分析 Agent 或后置 Review。

**该筛查沿用冻结的 implementation 上下文，并没有完成“正式 plan 状态直接输出核心”的集成或对照。** 工具协议、保存形式与最新动作消息共同变化，不能分别归因，也不能宣称减少了生产语义翻译或调用次数。

- 实际模型 MiniMax-M2.7-highspeed，1 次模型响应，生成 51.797 秒；包含全部使用量的原响应保留。
- 正确调用发布工具，核心装配后源码检查、实际文件执行和结果结构校验通过。
- 同一程序执行原始输入、四维等量、部分并列、唯一最大、单项、空集 6 个变体：5 个非空完成保存，1 个空集 no_data_found；四个分类的结构化分布核对通过。
- 完整报告业务验收失败：原样本 2022/2023 均 3 条安装记录，源码 idxmax 只选 2022；三年各一条时也只选 2021。分类比较函数正确，没有同步控制安装年份选择。
- 单项数据为一台运行中设备，固定建议仍称“当前非运行状态设备需要评估原因，制定维护或处置计划”；建议不随零命中改变。
- 报告将额定功率容量作为产能规划参考上限，但缺少产量、节拍或单位功率到产能的规则，不能把 kW 直接视为实际产能上限。额定与实际功率的局部区分没有补上该依据。
- 安装表 Markdown 显示 installation_year 内部字段名，尚未实现一致的业务可读显示。

以上错误均在**发布的初始核心源码内**，不是宿主插入或变更。结构化计数正确和身份封存均未认证这些结论。没有新增修复或另外两次生成，也没有进行成本模型发布筛查：按同根错误即停止候选的决定结束本候选。

## 取舍

版本身份与无模型重放边界成立；业务准确性和全链路性能没有通过。原型保持隔离，不扩大持久化或协议改造，不注册生产。

这个结果不能证明所有错误都由模型能力引起，也不能否定未执行的完整 plan-to-core 方案；它足以否定“只封存整份实现源码就能解决现有正文错误”。下一项诊断应针对初次生成内部为何算法/表达偏离已给依据，区分任务组织、上下文干扰和模型能力；不再把更多输出结构约束当作业务修正。
