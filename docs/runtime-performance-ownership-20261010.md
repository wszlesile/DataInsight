## 设计问题与改动

1. **历史程序的执行方式在交接时丢失。** 工作视图曾把 `definition_source` 复制为 `code`，使修复阶段看见两种互斥执行方式。现在保留原始执行端口并移除视图中的冗余别名，审计原始记录仍保留。
2. **正式结果消费接口不能读取已登记查询来源。** `ExecutableResults.table` 现在按已登记身份读取查询来源或计算结果；不把来源伪装成计算事实。已有字段投影与重命名沿用真实 receipt 映射，未绑定视图可以展示，但不会自动获得证据身份。
3. **结构性错误缺少修复所需信息。** 缺失字段错误返回实际缺失字段、可用字段和行数，不输出业务数据值，也不判断业务语义。
4. **上下文摘要在多个消费者处重复生成。** 同一历史前缀在 Prompt 构建时被连续压缩三次；收尾的 rolling summary 与 analysis state 也重复压缩。按数据库、会话、完整历史输入与压缩配置精确复用成功摘要，进程缓存限制为 128 项。历史答案、来源范围、轮次身份或配置变化会产生新的输入；模型失败与空返回的降级摘要不作为成功结果缓存。历史前缀读取不覆盖整段会话的持久记忆。
5. **时序模式定义到达语义规划阶段过晚。** raw / sample / aggregate 的定义现在由 `context.time_series` 单点维护，在 understand / plan 阶段按能力引入；查询合约复用相同定义，具体 SQL 方言仍在查询阶段提供。没有添加模型调用或语义评判关卡。
