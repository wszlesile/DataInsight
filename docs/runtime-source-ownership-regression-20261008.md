# UNS 来源身份与范围契约回归（2026-10-08）

基线：`0ab8781`；本轮修改在工作区。正式结果使用正常本地 API、真实 UNS 导入、真实模型网关与物理查询；SQLite、会话及产物均为本地隔离记录，没有修改远程历史轮次或部署服务。模型为 DeepSeek-V4-Flash。

## 定位与实现

1. Preparation 的 semantic_selection 原先直接用检索结果替换轮次来源目录。改为合并候选，同 ID 优先保留轮次快照中的来源身份、Schema 和查询入口；未召回的用户来源仍参与选择，辅助检索来源仍可选用。
2. 轮次快照按真实绑定关系区分 user_selected、conversation_candidate；检索扩展标为 semantic_candidate。选择阶段接收原始问题及用户来源的完整字段，不靠相似名称推断物理映射。身份随 Runtime 的来源视图继续传递。
3. UNS 引用目标通过 reference_target 独立传递，与业务 JOIN/relationships 分离。空业务关系不能推导“引用节点没有引用目标”。
4. UNS 关系型节点的定义只枚举业务字段，标记 schema_scope=declared_business_fields，不将它当成完整物理列集合。该范围同时进入选择、实现和表达阶段；表达仍有失真，不能以增加说明就宣布解决。
5. 全部事实 unresolved 时允许合法空选择，移除强迫至少选一个无关来源的契约要求，保留来源 ID、事实 ID、依赖和直接覆盖的结构要求。
6. 原生定义接口明确 query_constraints.aggregation 的 grain/metric 是字符串，与 register_query 的 tuple 不同；results.chart 读取保存的结果，不接受另传 data，新的分箱/统计结果仍登记为 calculation。

没有增加语义评分、LLM 语义复核、按语义判断自动重试、按会话名称分支或减少检索/分析能力。

## 独立真实数据核对

通过正常查询 helper 读取 `uns_get('lst-test/test02')`：

- SELECT * LIMIT 5 返回 `_id`、`value`、`timeStamp` 三列，而业务 Schema 仅声明 value。
- 总行数与非空 value 均为 33,142；不同 value 为 101；最小 0、最大 100；平均值 50.07413553798805。
- SELECT DISTINCT * 后的完整物理行仍为 33,142，完整物理行重复为零。因此 value 重复不能冒充完整行重复。

上述独立检查用于人工验收，没有反馈给本次模型触发语义重试。

v3 报告已将重复边界写为取值重复，但仍断言“没有时间字段”，并把“重复记录数（总记录数 − 去重取值数）”绑定为 33,142，而该减法为 33,041。两种真实统计（重复取值涉及的全部行、每个取值保留一行后的多余行）仍被表达阶段混用。引用可解析不证明周边文字语义正确。

## 继续推进的设计边界

- 来源身份传递修复是基础，不代表物理结构已就绪。需要按实际访问入口取得可追溯的完整物理列集合，再与平台业务字段定义合并；不能单靠提示语让模型猜未声明的系统列。
- Preparation 全部事实无支持的合法空选择，需要作为本轮已完成的来源能力结果进入 Runtime；目前仍在 understand 状态强迫规划，导致 6 次无工具续跑。应直接完成来源缺口表达，不重新选择无关表。
- 查询失败要保留来源可用性状态和失败回执，与查询成功空集区分；不可访问不能通过构造包含零行数的临时 DataFrame 伪装成查询成功，也不应进入无意义的多轮程序修复。
- 保存事实的字段要携带其统计对象、粒度、总体、算法和单位，再由同一消费绑定交给表达；“涉及重复的全部行”和“多余重复行”必须以各自事实身份表达。需要改生产事实协议，不加报告语义验收器。
- 表格/图表应直接消费已保存的结果视图；任意重新组装 DataFrame 和展示阶段新聚合继续造成 unbound。应完善 calculation → view → artifact 的统一执行接口及模型可见契约，保留完整分析能力。
