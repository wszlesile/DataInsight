## 问题归类

1. **查询粒度错误**：第二次 Probe 将检测记录连接过程采样后直接计数，采样会按同批次检测记录重复展开。校验正确拒绝，下一次 Probe 改用已有汇总字段，一次修复成功。
2. **结果列与源字段混淆**：首份正式代码的 `numeric_columns` 填入了 SQL 聚合前的字段名，而非实际结果别名。当前文档已有别名说明；不能继续只加同义禁止句。模型一次局部修复完成。
3. **来源字段归属错误**：设备事件查询使用不存在的 `batch_id`，正确字段为 `linked_batch_id`。完整 Schema 已提供，模型随后修正。不能把本次错误简单归因为缺 Schema。
4. **环境事务状态异常**：后续执行在首条正常查询就报事务中止。新的独立 API 实例和原生 psycopg2 新连接、提交或不提交授权事务，SELECT 1 均复现；驱动显示空闲状态，服务端却报告 DuckDB 事务已中止。尚未证明由哪条请求触发，不能据此修改洞察连接池或归咎于模型。
5. **首份程序的语义与可复跑性问题**：低侧偏离已按 `spec_lower - test_value` 计算，但仍将不同检测单位的绝对偏离量一起求均值、取最大值和排名；报告多处直接写入 Probe 观察数值；将一般质量异常候选解释成物料来源因素，且表格按频次排序、正文又给另一种优先级。这些问题发生在事务错误以前，环境恢复并不能使其自动通过。
6. **中间进度语言**：多次面向用户的模型进度为英文，当前用户问题为中文；记录为已有语言要求未稳定落实，不混入计算正确性结论。
