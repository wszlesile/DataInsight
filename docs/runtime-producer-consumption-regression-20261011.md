## 本轮改动及设计边界

本地工作区后端连接 192.168.236.53 的真实数据、模型网关和 FedQuery，刷新原轮次；不部署远程后端，不新增会话轮次，不添加语义评分、关键词判断或语义重试。

- **组合图表丢失来源身份。** `build_chart_suite` 内部先将 DataFrame 规范化成行列表，再交给子图。现在保留原始输入回执，并记录子图实际使用的参数，不重复计算或用相等数值猜来源。同时尊重显式 `include_line=True`，不再因时间字段识别不成功而改成柱图。
- **查询来源不能参与数学极值。** 极值现在消费已登记查询来源或计算结果；查询来源必须显式指定实际数值字段。并列、缺失、全空和无单位均保留原有数学处理。极值匹配行携带实际筛选操作的回执；没有生成复制计算来伪装原生查询结果。计算结果仍保留原来的计划结果身份与跨执行隔离。
- **表达反馈丢失已存在的查询口径。** 候选反馈现在交接真实 `query_constraints`、`analysis_scope`、`query_scope` 与 `temporal_coverage`。表达阶段复用同一份时序模式定义。没有新的模型阶段；时间覆盖元数据仍只描述请求时段与执行时刻，不认证新鲜度或缺失率。
- **转换后写入别名丢失字段关系。** 记录实际 `pd.to_numeric` 转换及同一 DataFrame 内的 Series 别名赋值，保留转换参数和字段映射。任意乘法、普通副本、外部 Series 或失去原 Frame 的 Series 不会凭值相等取得证据。普通 pandas 调用返回值不变；捕获关闭时不会记录回执。
- **查询来源的极值目录。** 查询来源判断指向真实查询与字段，不构造不存在的计算事实节点；缺少实际字段来源映射时保持 unresolved。该边界在完整复跑后以相关测试进一步检查。

## 仍未收敛的问题与继续方向

1. **查询约束和输出粒度仍有首次提交错误。** 702/711 的查询约束结构问题、704 的 `window` 粒度与实际一行统计结果不符，仍触发技术修复。这是首次实现的 API/数据形状交接问题，不能归为已解决或用换案例掩盖。
2. **自由表达未稳定消费执行结果。** 703 使用了 `report_text` 端口但未插入结果引用；不能以报告有数字就自动匹配相同值。705/712 能绑定引用，也不能由数值引用认证周围的叙述。
3. **趋势、分布与完整性解释仍超出明确计算依据。** 最终报告将均值接近中位数解释成对称随机跳动、将 60 个聚合窗口解释成完整覆盖，又写出约 40 个窗口落在某范围及高低窗口位于序列两端等不充分的结论。请求时段右边界导致的不完整窗口，与执行时刻尚未到达边界是不同事实。
4. **部分来源无数据的正式交付仍不足。** 709 首份程序实际查询到 dhb001 无结果并在报告披露；最终结果的 used scope 为 [26]，而选择 scope 为 [26,37]。应使来源级无数据观察成为正式执行产物的一部分，保留独立来源身份与失败/空结果口径，而不是靠报告转述 Probe 或省略该来源。

下一轮沿统一分析定义推进：让趋势、覆盖与分布判断在正式程序中拥有明确的输入总体和实际算法，表达阶段消费这些已执行产物并自由组织报告。保留会话内澄清的既有边界，不把普通分析问题交给澄清，也不添加语义正确性评分或自动改写重试。
